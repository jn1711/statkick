## 1. Назначение и цели системы

### 1.1 Цель проекта

Разработка аналитической веб-платформы **«StatKick»**, предназначенной для:

- Обработки массивов статистических данных (Big Data) футбольных матчей
- Прогнозирования результатов будущих встреч
- Оценки долгосрочных исходов турниров
- Симуляции гипотетических игровых сценариев

### 1.2 Задачи системы

| № | Задача | Описание |
|---|--------|----------|
| 1 | **Агрегация данных** | Структурирование исторических данных о матчах, командах и игроках |
| 2 | **Расчёт вероятностей** | Математическое моделирование исходов матчей |
| 3 | **Оценка внешних факторов** | Анализ влияния нагрузки, перелётов и кадровых потерь |
| 4 | **Моделирование турниров** | Многовариантное моделирование методом Монте-Карло |
| 5 | **Интерактивные инструменты** | Симуляция тактических настроек и гипотетических трансферов |

## 3. Детальное описание функционала по страницам

Приложение состоит из **6 ключевых страниц**, объединённых сквозным навигационным меню.

### 3.1 Главная страница (Dashboard)

**Назначение:** Первичное ознакомление с текущим состоянием футбольного дня и анонсирование аналитических инсайтов.

| Компонент | Описание |
|-----------|----------|
| **Календарь матчей** | Интерактивная лента на 7 дней с фильтрацией по топ-5 лигам (Англия, Испания, Италия, Германия, Франция) и Лиге чемпионов УЕФА |
| **Выбор лиги** | Выпадающий список: Premier League, La Liga, Bundesliga, Serie A, Ligue 1, UCL, Europa League, World Cup 2026 |
| **Динамическая подгрузка** | При смене лиги календарь и ближайшие матчи загружаются через API без перезагрузки страницы |
| **Детектор сенсаций** *(Upset Alert)* | 3 матча дня, где вероятность победы аутсайдера превышает букмекерские ожидания на ≥15% (на основе кадровых потерь фаворита и аномальных xG) |
| **Глобальные тренды** | Динамические графики: средняя результативность лиг, % домашних побед, частота сухих матчей |

### 3.2 Страница анализа матча (Match Analytics)

**Назначение:** Детальный разбор конкретного противостояния.

#### Head-to-Head (H2H)
- Сравнение результатов последних **10** очных встреч
- Тренды результативности: атакующий и оборонительный xG за последние **5** матчей каждой команды

#### Прогноз ИИ
- **Круговая диаграмма** вероятностей: $P_1$ (победа А), $X$ (ничья), $P_2$ (победа Б)
- **Точный счёт** на основе двухфакторного распределения Пуассона

#### Индекс усталости (Fatigue Index)
- Графическая шкала (батарейка / прогресс-бар) для каждой команды
- Расчёт на основе дней отдыха и дальности перелётов за последние **14 дней**

#### Интерактивный симулятор тактики
- **Слайдер** тактики: от `-5` (оборона) до `+5` (атака)
- Мгновенный пересчёт базовых параметров xG и обновление прогноза

#### Источник данных
- Отдельный блок с указанием источника прогноза: **Football-Data / StatsBomb / приближённый xG**

### 3.3 Аналитика Лиг и Турниров (League Simulation)

**Назначение:** Долгосрочное прогнозирование итогов сезонов.

| Компонент | Описание |
|-----------|----------|
| **Прогнозная таблица** | Сортировка по математическому ожиданию очков (xPTS) к концу сезона |
| **Распределение Монте-Карло** | BarChart вероятностей занятия мест (1–20, по числу команд лиги) по итогам **10 000** симуляций |
| **Сетка плей-офф** | Дерево турнира с % прохода на каждом узле (1/8, 1/4, 1/2, финал) |
| **Сезонный режим** | Кнопка «Симулировать сезон» с выбором сезона (2025-26, 2026-27) |
| **2 сезона вперёд** | Последовательная симуляция: сезон N, затем N+1 на основе итогов сезона N |

### 3.4 Виртуальный трансферный симулятор (What-If Transfer Tool)

**Назначение:** Оценка влияния отдельного игрока на командный атакующий/оборонительный потенциал.

- **Интерфейс:** выпадающие списки «Из команды» → «Игрок» → «В команду»
- **Алгоритм пересчёта:**
  1. Получение `Player.xG90`, `Player.xA90`, `Player.minutes` из БД
  2. Коэффициент адаптации: `max(0.6, 1 - (age - 23) * 0.02)`
  3. Коэффициент сыгранности: `0.9` (первый сезон)
  4. Пересчёт командного xG: сумма `xG90 * minutes/90` + вклад нового игрока
  5. Визуализация «до/после» в виде столбчатой диаграммы

### 3.5 Описание методологии (Methodology)

**Назначение:** Математическое обоснование работы платформы (для академической ценности при защите).

- Подробное описание формул расчёта xG
- Индекс усталости
- Распределение Пуассона
- Принципы алгоритма Монте-Карло

### 3.6 Турниры (Tournaments)

- **Champions League:** формат 2024-25 (36 команд, лиговая фаза 8 матчей)
- **Europa League:** отдельная вкладка и календарная сетка
- **World Cup 2026:** 48 команд, 12 групп, выход в плей-офф 1/16 (топ-2 + 8 лучших третьих)

## 5. Математические модели и алгоритмы

### 5.1 Двухфакторная модель Пуассона

Используется для прогнозирования точного счёта матча.

$$P(k) = \frac{\lambda^k e^{-\lambda}}{k!}$$

Где:
- $k$ — количество голов
- $\lambda$ — среднее ожидаемое количество голов, рассчитываемое на основе атакующей силы команды А и оборонительной слабости команды Б с поправкой на фактор домашнего поля

**xG рассчитывается двумя режимами:**
1. **Точный:** из StatsBomb Open Data (события `shot`, поле xG)
2. **Приближённый:** `xG = shots_on_target * 0.1 + total_shots * 0.03 + corners * 0.02` (если StatsBomb недоступен)

### 5.2 Индекс усталости и загруженности (Fatigue Index — FI)

Рассчитывается для корректировки базовых параметров $\lambda$ перед матчем:

$$FI = w_1 \cdot D + w_2 \cdot T$$

Где:
- $D$ — штраф за интервал между матчами (экспоненциальный штраф при < 4 дней отдыха)
- $T$ — количество away-матчей за 14 дней $\times 0.02$ (временная заглушка до геокодинга стадионов)
- $w_1, w_2$ — весовые коэффициенты, откалиброванные по историческим данным

**Ограничение:** $FI \leq 0.3$ (максимум 30% штрафа).

### 5.3 Симуляция Монте-Карло

Для прогнозирования итоговой таблицы чемпионата:

1. Оставшиеся матчи моделируются **10 000 раз**
2. На каждом шаге результат игры разыгрывается случайным образом согласно рассчитанным вероятностям
3. Итоговые вероятности чемпионства / вылета = частота соответствующих исходов по всей совокупности итераций

**Оптимизация выполнения:**
- Итерации выполняются чанками по **1000**
- Прогресс симуляции сохраняется в Redis
- Целевое время: **≤ 3 секунд** для полного прогона при включённом кэше/чанках

**Симуляция 2 сезонов:**
- Итоги сезона N (таблица и обновлённые командные метрики) используются как вход для сезона N+1.

### 5.4 Симуляция трансферов

Формула нового командного xG после трансфера:

$$\text{newXg} = \sum_{i \in \text{team}} xG90_i \cdot \frac{minutes_i}{90} + xG90_{new} \cdot adaptation \cdot chemistry \cdot \frac{minutes_{new}}{90}$$

## Приложения

### A. Схема базы данных (Prisma ORM)

```prisma
generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Team {
  id            String   @id @default(uuid())
  name          String   @unique
  shortName     String?
  country       String
  leagueId      String?
  league        League?  @relation(fields: [leagueId], references: [id])
  homeMatches   Match[]  @relation("HomeTeam")
  awayMatches   Match[]  @relation("AwayTeam")
  players       Player[]
  xGHome        Float    @default(0)
  xGAHome       Float    @default(0)
  xGAway        Float    @default(0)
  xGAAway       Float    @default(0)
  homeAdvantage Float    @default(0.35)
  marketValue   Float    @default(0)
  europeanCoeff Float    @default(0)
  createdAt     DateTime @default(now())
}

model League {
  id              String   @id @default(uuid())
  name            String   @unique
  country         String?
  tier            Int      @default(1)
  teams           Team[]
  matches         Match[]
  season          String
  isCup           Boolean  @default(false)
  isInternational Boolean  @default(false)
}

model Player {
  id              String     @id @default(uuid())
  name            String
  teamId          String
  team            Team       @relation(fields: [teamId], references: [id])
  position        String
  xG              Float      @default(0)
  xA              Float      @default(0)
  xG90            Float      @default(0)
  xA90            Float      @default(0)
  minutes         Int        @default(0)
  games           Int        @default(0)
  marketValue     Float      @default(0)
  age             Int        @default(25)
  fitness         Float      @default(1.0)
  transferHistory Transfer[]
}

model Match {
  id           String   @id @default(uuid())
  date         DateTime
  leagueId     String
  league       League   @relation(fields: [leagueId], references: [id])
  homeTeamId   String
  homeTeam     Team     @relation("HomeTeam", fields: [homeTeamId], references: [id])
  awayTeamId   String
  awayTeam     Team     @relation("AwayTeam", fields: [awayTeamId], references: [id])
  homeGoals    Int?
  awayGoals    Int?
  homeXg       Float?
  awayXg       Float?
  result       String?
  season       String
  matchday     Int      @default(1)
  isPlayed     Boolean  @default(false)
  isSimulated  Boolean  @default(false)
  fatigueHome  Float    @default(0)
  fatigueAway  Float    @default(0)
}

model Transfer {
  id           String   @id @default(uuid())
  playerId     String
  player       Player   @relation(fields: [playerId], references: [id])
  fromTeamId   String
  toTeamId     String
  season       String
  fee          Float    @default(0)
  isLoan       Boolean  @default(false)
  createdAt    DateTime @default(now())
}

model SeasonSimulation {
  id           String   @id @default(uuid())
  leagueId     String
  season       String
  iterations   Int      @default(10000)
  results      Json
  createdAt    DateTime @default(now())
}
```

### B. Ключевые метрики

| Метрика | Описание |
|---------|----------|
| **xG** | Ожидаемые голы (Expected Goals) |
| **xGA** | Ожидаемые пропущенные голы (Expected Goals Against) |
| **xA** | Ожидаемые голевые передачи (Expected Assists) |
| **xG90** | xG за 90 минут |
| **xA90** | xA за 90 минут |
| **adaptation** | Коэффициент адаптации игрока (0.6–1.0) |
| **chemistry** | Коэффициент сыгранности (0.9 для новичка) |
| **europeanCoeff** | Коэффициент УЕФА команды |
| **xPTS** | Математическое ожидание очков (Expected Points) |
| **FI** | Индекс усталости и загруженности (Fatigue Index) |

### C. Критичность изменений ТЗ

| Что менять | Насколько критично |
|------------|-------------------|

| Новые страницы (турниры) | 🟡 Средне — добавить в ТЗ |
| Трансферный симулятор | 🟡 Средне — переписать алгоритм |
| Источники данных | 🟢 Низко — добавить в приложение |
