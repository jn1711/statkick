## 1. Описание проекта

**StatKick** - это веб-приложение для анализа футбольных матчей, прогнозирования исходов и моделирования турнирных сценариев на основе статистики команд, игроков и матчей. Проект ориентирован на демонстрацию Big Data-подхода в спортивной аналитике: данные агрегируются в реляционной базе, обрабатываются серверной логикой, а пользователь получает интерактивные прогнозы, графики и симуляции.

Приложение реализовано как full-stack TypeScript-проект:

- клиентская часть: React, Vite, React Router, Tailwind CSS;
- серверная часть: Hono, tRPC, Node.js;
- база данных: MySQL через Drizzle ORM;
- визуализация: Recharts, Framer Motion, Three.js/React Three Fiber для 3D-поля;
- математические расчеты: собственные TypeScript-модули для Пуассона, индекса усталости и Монте-Карло.

Система поддерживает работу как с MySQL, так и с fallback-набором футбольных данных, если подключение к базе не настроено. Это позволяет демонстрировать проект локально без обязательной подготовки инфраструктуры.

## 2. Цели и задачи

### 2.1 Цель проекта

Разработать аналитическую платформу, которая позволяет пользователю:

- просматривать матчи по сезонам и лигам;
- анализировать конкретный матч и вероятности исходов;
- видеть форму команд, ожидаемые голы и индекс усталости;
- моделировать итоговую таблицу лиги;
- оценивать влияние виртуального трансфера игрока;
- изучать методологию расчетов в понятном академическом формате.

### 2.2 Основные задачи

| N | Задача | Описание |
|---|--------|----------|
| 1 | Агрегация данных | Хранение лиг, команд, игроков, матчей, событий и пользователей в MySQL |
| 2 | Прогноз матча | Расчет вероятностей П1/X/П2 и наиболее вероятного счета |
| 3 | Анализ формы | Учет последних матчей, xG/xGA, домашнего и гостевого фактора |
| 4 | Индекс усталости | Коррекция прогноза с учетом дней отдыха и условной дистанции поездки |
| 5 | Симуляция лиги | Моделирование оставшихся матчей методом Монте-Карло |
| 6 | Трансферный сценарий | Пересчет влияния игрока на xG, xA и оборонительные метрики команд |
| 7 | Визуализация | Представление данных через графики, таблицы, карточки и интерактивные элементы |

## 4. Функциональные требования

### 4.1 Главная страница `/`

Главная страница служит обзорным дашбордом футбольной аналитики.

Функции:

- выбор сезона;
- фильтрация матчей по лиге;
- переход к анализу выбранной лиги;
- отображение календаря или списка матчей;
- отображение статуса матчей: запланирован, идет, завершен, симулирован;
- вывод детектора потенциальных сенсаций;
- отображение глобальных трендов через графики;
- 3D-визуализация футбольного поля в первом экране;
- синхронизация локально сохраненных результатов симуляций матчей.

Основные источники данных:

- `league.list`;
- `match.list`;
- `match.upsets`;
- `league.trends`.

### 4.2 Страница матча `/match/:id`

Страница предназначена для детального анализа конкретной игры.

Функции:

- вывод команд, даты, счета и статуса матча;
- отображение коэффициентов, если они есть в данных;
- расчет вероятностей исходов П1/X/П2;
- отображение наиболее вероятного счета;
- графики формы хозяев и гостей;
- H2H-история очных встреч;
- расчет и визуальное отображение индекса усталости;
- тактический слайдер, который изменяет ожидаемые xG;
- учет локально сохраненного результата симуляции для запланированного матча.

Основные источники данных:

- `match.getById`;
- `match.predict`.

### 4.3 Страница симуляции лиги `/league/:id`

Страница предназначена для долгосрочного прогнозирования сезона.

Функции:

- загрузка информации о лиге;
- построение текущей или прогнозной таблицы;
- запуск симуляции оставшихся матчей;
- расчет ожидаемых очков и вероятностей итоговых мест;
- визуализация чемпионских вероятностей и распределений;
- сортировка команд по расчетным показателям.

Основные источники данных:

- `league.list`;
- `league.standings`;
- `league.simulate`.

### 4.4 Виртуальный трансферный симулятор `/transfer`

Инструмент предназначен для оценки влияния игрока на старую и новую команду.

Функции:

- поиск игрока по имени или команде;
- фильтрация игроков по позиции;
- фильтрация по команде;
- выбор старой и новой команды;
- автоматическое определение текущей команды игрока;
- отдельная логика для полевых игроков и вратарей;
- расчет влияния на xG, xA, xGA и оборонительные показатели;
- сравнение метрик до и после трансфера на графике.

Основные источники данных:

- `player.list`;
- `player.transferSimulate`.

### 4.5 Страница методологии `/methodology`

Страница объясняет математические принципы проекта.

Функции:

- описание двухфакторной модели Пуассона;
- описание индекса усталости;
- описание xG, xGA и xA;
- описание симуляции Монте-Карло;
- описание трансферной модели;
- вывод формул, пояснений и итоговых метрик точности.

### 4.6 Страница авторизации `/login`

Страница предназначена для входа пользователя через доступную OAuth/session-интеграцию.

Функции:

- отображение интерфейса входа;
- обработка пользовательской сессии;
- поддержка ролей `user` и `admin` на уровне схемы данных.

## 6. API и серверная логика

### 6.1 Hono-приложение

Серверная точка входа находится в `api/boot.ts`.

Требования:

- принимать tRPC-запросы по пути `/api/trpc/*`;
- ограничивать размер тела запроса до 50 MB;
- обрабатывать OAuth callback;
- в production обслуживать собранные статические файлы frontend;
- возвращать `404` для неизвестных `/api/*` маршрутов.

### 6.2 tRPC-роутеры

Корневой роутер `appRouter` должен включать:

- `ping` - проверка доступности API;
- `auth` - авторизация и сессии;
- `match` - матчи и прогнозы;
- `league` - лиги, таблицы и симуляции;
- `player` - игроки и трансферный симулятор;
- `methodology` - методологические данные.

### 6.3 Match API

| `match.predict` | Расчет прогноза матча, xG, вероятностей и формы |
| `match.upsets` | Поиск матчей, где вероятность аутсайдера выше ожиданий по коэффициентам |

### 6.4 League API

| Метод | Назначение |
|-------|------------|
| `league.list` | Получение списка лиг и сезонов |
| `league.standings` | Получение таблицы команд |
| `league.simulate` | Запуск Монте-Карло симуляции сезона |
| `league.trends` | Расчет общих трендов по матчам |

### 6.5 Player API

| Метод | Назначение |
|-------|------------|
| `player.list` | Получение игроков с данными команды |
| `player.transferSimulate` | Расчет влияния виртуального трансфера |

### 6.6 Fallback-данные

Если переменная `DATABASE_URL` отсутствует или запрос к MySQL вернул пустой набор/ошибку, сервер должен использовать fallback-данные из `api/data/fallback-football.ts`.

Это требование нужно для:

- локальной демонстрации без базы;
- устойчивости интерфейса при ошибках подключения;
- тестирования клиентской части независимо от инфраструктуры.

## 7. Математические модели

### 7.1 Распределение Пуассона

Модель используется для оценки вероятности количества голов команды.

```text
P(k) = (lambda^k * e^(-lambda)) / k!
```

Где:

- `k` - количество голов;
- `lambda` - ожидаемое количество голов;
- `e` - основание натурального логарифма.

`lambda` рассчитывается на основе:

- атакующей силы команды;
- оборонительной слабости соперника;
- домашнего/гостевого фактора;
- индекса усталости;
- исторической формы и xG.

### 7.2 Вероятности исходов

Для матча строится матрица вероятностей счета. Затем значения суммируются:

- победа хозяев: все счета, где `homeGoals > awayGoals`;
- ничья: все счета, где `homeGoals = awayGoals`;
- победа гостей: все счета, где `homeGoals < awayGoals`.

Наиболее вероятный счет определяется как пара значений с максимальной вероятностью в матрице.

### 7.3 Индекс усталости

Индекс усталости корректирует силу команды перед матчем.

```text
FI = w1 * D + w2 * T
```

Где:

- `D` - штраф за недостаток дней отдыха;
- `T` - штраф за условную дистанцию поездки;
- `w1`, `w2` - весовые коэффициенты.

Требования:

- диапазон индекса должен быть ограничен безопасными значениями;
- высокий индекс должен снижать атакующий потенциал;
- интерфейс должен показывать текстовое описание и цветовой статус усталости.

### 7.4 Симуляция Монте-Карло

Модель используется для прогнозирования таблицы лиги.

Алгоритм:

1. Получить текущие команды и матчи лиги.
2. Построить исторические профили команд.
3. Для каждого незавершенного матча рассчитать вероятности исходов.
4. Провести многократное моделирование оставшейся части сезона.
5. Суммировать очки, места и вероятности чемпионства.
6. Вернуть таблицу с ожидаемыми результатами.

### 7.5 Трансферная модель

Модель оценивает изменение командных метрик при переходе игрока.

Для полевых игроков учитываются:

- индивидуальный `xg`;
- индивидуальный `xa`;
- позиция;
- вклад в атакующий потенциал старой и новой команды;
- коэффициент адаптации.

Для вратарей дополнительно учитывается влияние на:

- `xGA`;
- защитный рейтинг;
- снижение или рост ожидаемых пропущенных голов.

## 9. Нефункциональные требования

### 9.1 Производительность

- Сборка frontend должна выполняться через Vite.
- Серверная production-сборка должна выполняться через esbuild.
- Повторяющиеся API-запросы должны кешироваться на клиенте средствами TanStack React Query.
- Монте-Карло симуляция должна возвращать результат за приемлемое для UI время.

### 9.2 Надежность

- При отсутствии MySQL приложение должно продолжать работу на fallback-данных.
- Все входные параметры tRPC-методов должны валидироваться через Zod.
- Сервер должен возвращать предсказуемые структуры данных.
- Клиент должен показывать loading/error/empty состояния.

### 9.3 Безопасность

- Секреты и параметры подключения должны храниться в `.env`, а не в коде.
- Авторизационные cookie должны обрабатываться серверной логикой.
- Роли пользователей должны храниться в БД.
- API не должен раскрывать служебные ошибки пользователю в сыром виде.

### 9.4 Поддерживаемость

- Код должен быть написан на TypeScript.
- Домены должны быть разделены на роутеры: матчи, лиги, игроки, методология, авторизация.
- Математические функции должны находиться отдельно в `api/math`.
- Схема БД должна поддерживаться через Drizzle.
- Компоненты интерфейса должны переиспользоваться.

## Итоговые критерии приемки

Проект считается готовым, если:
